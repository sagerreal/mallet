## [HIGH] `modules/jobs/api/field-router.ts`:133
**Problem:** The new `v1.field.setVisitStatus` / `v1.field.setVisitEnroute` endpoints act on a VISIT but are authorised at JOB granularity. `assertOnJobIfTech` calls `Job.isAssignedTo(userId)` (modules/jobs/domain/job.ts:399), which is true if the caller is the job-level `assigneeUserId` OR the assignee of ANY non-canceled visit. **Failure:** Org O. Job J (assignee_user_id = tech A) has two placed visits: V1 (assignee tech A) and V2 (assignee tech B). Tech A calls `v1.field.setVisitStatus({ jobId: J, visitId: V2, status: "complete" })` with his own token. assertOnJobIfTech → isAssignedTo(A) → true via the job-level assignee. **Fix:** Add a visit-level gate for tech callers: after resolving the visit, require `visit.props.assigneeUserId === principal.userId` (falling back to the job-level assignee only when the visit has no assignee), and return FORBIDDEN otherwise.
