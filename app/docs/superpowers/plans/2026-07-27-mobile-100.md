# Road to 100 — mobile feel

Mallet went native on iPhone on 2026-07-27 (Capacitor shell → `app.trymallet.com`). An audit
built a 7-category weighted rubric from Apple HIG, WCAG 2.2, Core Web Vitals and the WebKit /
Capacitor docs, then scored the app against **measured** production numbers at the iPhone 17 Pro
viewport (402×874 @3×).

**Raw score 34.1/100.** That number is a floor, not the truth: 5 of the 9 critical/high failures
did not survive adversarial verification, and scoring ran before that check. Stripping the
refuted ones puts it near **55**.

| Category | Weight | Raw | Post-refutation |
|---|---|---|---|
| Tap Reliability & Reach | 22% | 41 | ~65 |
| Touch Feedback & Responsiveness | 20% | 76 | ~85 |
| Load & Offline on Bad Cellular | 16% | 36 | ~58 |
| Text Entry & Form Ergonomics | 14% | 24 | ~27 |
| Field Legibility | 13% | 52 | 52 |
| Native Shell Integrity | 10% | 44 | 44 |
| Motion, Focus & Loading | 5% | 40 | 40 |

---

## Three decisions that block a literal 100

These are product calls, not defects. Until Owen rules, the affected criteria cannot pass.

1. **Dark mode: system-driven or manual toggle?** The rubric wants `prefers-color-scheme` parity
   (HIG). Mallet ships a deliberate manual toggle in `components/shell/topbar.tsx` and
   `html{color-scheme:light}`, so the system setting is ignored — dark tokens exist but only
   under `[data-theme="dark"]`. Keeping the toggle means `dark-mode-system-parity` never passes.
   *Recommendation: honour the system by default, keep the toggle as an override.*

2. **Dynamic Type / relative typography?** All 9 `--type-*` tokens are absolute px, so the OS
   text-size setting does nothing. Converting to `rem` is a large change that reflows every
   desktop table. *Recommendation: do it, but last — it is the single largest item here.*

3. **Tab bar contents.** Front Desk and Pricebook are top-level pillars on desktop but reachable
   on a phone only via **More**. Five tabs is the HIG maximum, so adding means trading something
   out. *Needs Owen: are they phone-level pillars at all?*

## Phases, ordered by (user impact × weight) ÷ effort

### Phase 1 — touch & text floors ✅ SHIPPED (this PR)
The highest impact per unit of effort in the whole audit, and all of it in one stylesheet.

| Fix | Evidence before |
|---|---|
| 16px text-entry floor | 19 controls under 16px across 8 routes → iOS force-zoomed on every field tap |
| 44px primary targets | `.btn.sm` 79×40, `.chip` 40, `.iconbtn` 34×34 (incl. the #231 New button) |
| `.btn:focus-visible` | `.btn{outline:none}` beat the `:where()` rule at :462 — **no** keyboard ring on any button |
| `-webkit-touch-callout:none` on chrome | long-press on nav gave the iOS Copy/Look-Up sheet |
| `overscroll-behavior-y:none` | scroll chaining dragged the page behind inner lists |

Two non-obvious root causes, both worth knowing before touching this file again:
- The 16px rule **already existed** and still failed. `.field input[type=text]` (0,2,1) beats
  bare `input[type=text]` (0,1,1) whatever the source order, AND `COMPACT_INPUT` in
  `components/ui/input.tsx` sets `fontSize` **inline**, which no selector can reach. Hence one
  `!important`.
- The app-wide focus rule is wrapped in `:where()`, which contributes **zero** specificity, so
  `.btn` tied it and won on order.

Net: `e2e/mobile-floors.spec.ts` now holds both floors.

### Phase 2 — forms, and a credential leak
- **`/login` submits as a native GET before hydration**, putting the password in the URL,
  browser history and any access log. `<form>` has no `action` and its `onSubmit` only exists
  after React attaches. Measured exposure window: **48 ms** on fast wifi, **630 ms** on a 4×-CPU-
  throttled phone on 1.5 Mbps. Fix: `action` + a server action, or disable submit until hydrated.
- 41 money/rate/hours fields use `type="number"`; convert to `type="text" inputMode="decimal"`.
- 22 of 33 identity fields have no `autocomplete` token. 0 of 213 controls set `enterkeyhint`.
- `interactiveWidget: "resizes-content"` on the viewport export (one line) fixes web keyboard
  avoidance; the native shell already has `Keyboard.resize:"native"`.
- `scroll-padding-bottom` so a focused field is never behind the command bar + tab bar.

### Phase 3 — weight and first paint
- **~310 KB of JS per route** (measured via CDP `encodedDataLength`, cold cache). This is the real
  LCP lever — the LCP element is *text* on every route, so paint waits on hydration.
  ⚠️ Fonts are **88.5 KiB**, not the problem; font plumbing is already textbook (19 `@font-face`,
  100% WOFF2, `font-display` present, all `subsets:["latin"]`).
- Server-seed the first screen via tRPC `initialData` on `/dashboard`, `/pipeline`, `/tasks` —
  the pattern `resolveMe` already established.
- Drop `Space_Mono` 700 (one whole file for numeric accents).
- Service worker for mobile-web offline. The native shell already has `errorPath` → `offline.html`.

### Phase 4 — loading and motion
- **Zero skeletons and zero spinners exist app-wide** (`grep skeleton|shimmer|spinner` → 0 hits);
  six bare "Loading…" strings. Add a delayed-loading hook (300 ms before showing, 500 ms minimum
  once shown) so fast loads never flash.
- `prefers-reduced-motion` covers 14 of 20 `animation:` declarations — take it to 20.
- Two transitions animate layout properties (`grid-template-rows`, `all`); move to transform.
- Promote the duration/easing values already in use (49×120ms, 11×150ms) into tokens.

### Phase 5 — native shell
- `SplashScreen.launchAutoHide:true` + `launchShowDuration:1500` is a **timed** splash — HIG says
  hide as soon as ready. Set `launchAutoHide:false` and call `hide()` on first paint.
- Add `@capacitor/haptics`; a thin `lib/haptics.ts` port that no-ops when `window.Capacitor` is
  absent. Currently zero haptic call sites.
- **No back affordance anywhere** — `router.back()` appears 0 times. In a webview with no browser
  chrome, some screens are one-way.

### Phase 6 — legibility
- Input borders are `--line` at ~1.5:1 against the card; SC 1.4.11 wants 3:1. Add `--line-strong`.
- Promote decision-bearing values inside the phone breakpoint (don't change tokens globally —
  that reflows every desktop table).
- Then decisions 1 and 2 above.

## Honest ceiling

100/100 is not reachable while decisions 1–3 are open, and `dynamic-type-200pct` is a genuine
architectural change rather than a polish item. Everything mechanical can pass. Realistic target
once phases 1–6 land: **low 90s**, with the remainder being explicit product choices rather than
defects.

The rubric is a proxy. The goal is that a plumber can run their business one-handed in gloves on
bad cellular; the score is how we check.
